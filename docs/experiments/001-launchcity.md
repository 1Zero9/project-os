# Experiment 001 — LaunchCity

- **Experiment:** LaunchCity
- **Type:** Greenfield
- **Project OS version tested:** v0.1
- **Status:** Closed

## Provenance

The LaunchCity repository is the authoritative evidence source for this
record. This document summarises that evidence; it does not restate
LaunchCity's product decisions.

- Repository: https://github.com/1Zero9/launchcity
- Experiment 001 closure commit: `956cd06`
- Frozen Horizon recovery commit (visual-fidelity evidence): `6fcfa3a`

## Hypothesis

That a lightweight, evidence-driven decision process (Project OS v0.1) —
intake, relevant-knowledge capture, risk/failure naming, explicit Scope &
Stop checks at each phase boundary, and a learning record — would let
LaunchCity reach a shipped v0.1 with a validated data strategy, domain
boundary, architecture, product direction, experience architecture, and
visual direction, while avoiding both under-analysis (shipping on
unvalidated assumptions) and over-analysis (re-litigating decisions the
evidence already answered).

## Outcome

**SUPPORTED**, with one recorded qualification.

Every phase was frozen only after real evidence (live upstream API calls,
real browser screenshots, real production deploys, a real rate-limit
failure, a real successful cache write) and shipped without a blocking
unknown remaining. Three separate points where a plausible reason to reopen
a frozen surface appeared were each resolved by checking the frozen
requirement's own language rather than reopening.

Qualification: the process did not prevent one real instance of
unnecessary work caused by a local/remote evidence misread (see Mistakes).

## What Was Tested

Six sequential phase freezes (data strategy → domain validation →
architecture → product direction → experience architecture → visual
direction), two surface implementations, and a final release gate — each
run through Project intake, Relevant Knowledge, Risk & Failure, Scope &
Stop, and Learning capture.

## Material Value

- Real upstream data validation reversed two assumptions before any schema
  was built, avoiding a costly wrong data model.
- Real-browser validation caught structural layout bugs that passing
  type-check/lint/build did not surface.
- A visual-fidelity check against the actual original reference artefact
  (not a text description) caught high drift from the approved direction's
  defining perceptual signature that full structural/product compliance
  had completely masked.
- Repeated Scope & Stop checks correctly declined to reopen frozen surfaces
  on three separate occasions, each time by testing against the actual
  frozen requirement rather than a more polished hypothetical.

## Material Cost

- One piece of work (a production cache-path fix) was implemented, tested,
  committed and deployed based on evidence that was later found incorrect.
  The change was independently justified as hardening, but it was
  generated by a process misstep, not a real defect.

## Mistakes

- Local emulated evidence was mistaken for production evidence and acted
  on before being corrected.
- Unnecessary production work resulted from that misinterpretation.
- A visual direction was frozen in words without retaining the actual
  reference artefact for later comparison; the resulting drift was only
  caught by a separate, later review against the original artefact.

## Process Risks Observed

- Process/evidence-gathering activity is not inherently equivalent to
  progress — effort spent following an evidence misread grew directly out
  of trusting process-generated evidence over the real deployed target.
- Scope & Stop is stronger against known scope drift than against unknown
  omissions — a gap survived multiple freeze cycles undetected until
  directly questioned.
- Distinguishing a genuine defect from additional polish required explicit
  checking against the frozen requirement's own language in more than one
  case.
- Excessive evidence gathering was named as a risk to watch for but was
  not observed in this experiment.

## Final Release Result

**SHIP.** No release blockers found.

## Framework Changes

**NONE.** Project OS v0.1 remains frozen; no capability, template,
principle, agent, skill, Council, Brake, Eolas, orchestration, model
routing, or bootstrap change resulted from this experiment.
